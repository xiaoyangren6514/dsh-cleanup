# dsh-cleanup —— 安全地删除工作区目录与会话日志

中文 | [English](https://github.com/xiaoyangren6514/dsh-cleanup/blob/main/docs/DETAIL.en.md)

`dsh-cleanup` 是一个 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）插件，补上 DSH 刻意不提供的三个删除：

- **删除一个已注册工作区的真实目录**（递归）。
- **删除一个会话的事件日志**，连同它的子代理会话。
- **清空一个工作区的全部会话记录**，保留目录与注册。

DSH 本身对工作区只做「移除注册」——目录、文件与会话历史都留在磁盘上；对会话只有「归档」，没有删除。`dsh-cleanup` 补上这一段，同时把破坏面收窄：目标只能用 DSH 的身份指定、绝不用任意路径；每次删除都经过计划、复核与确认；默认结果是可恢复的回收站。

- 包名：`dsh-cleanup` 0.6.2
- 仓库：<https://github.com/xiaoyangren6514/dsh-cleanup>

## 能做什么

| 能力 | 位置 |
|---|---|
| 删除一个已注册的工作区目录（递归） | 侧栏工作区右键 → **删除工作区目录…** |
| 删除一个会话（含子代理会话日志） | 侧栏会话右键 → **删除会话…** |
| 清空一个工作区的全部会话记录（保留目录与注册） | 侧栏工作区右键 → **清空工作区会话…** |
| 会话列表按工作区筛选；子代理会话折叠到所属会话下 | 设置 → 存储清理 → 会话 |
| 复核弹窗逐行勾选目标（每个目标一个复选框，含**全选** / **反选**） | 复核弹窗 |
| 逐节点选择会话家族：子代理日志以树呈现，每个节点一个复选框，父节点三态 | 复核弹窗 |
| 可选的用量洞察：每个会话的令牌数与缓存命中率、own/family 合计、按用量排序 | 设置 → 存储清理 → 会话 → **用量** 开关 |
| 回收站记录子代理 family：`子代理` 徽标与 `父会话` 行 | 设置 → 存储清理 → 回收站 |
| 存储总览：大小、批量选择、排序与归档筛选 | 设置 → **存储清理** |
| 在文件管理器中打开工作区目录、会话目录、回收站条目或投影缓存目录 | 工作区 / 会话 / 回收站行、复核摘要、回收站页签头部 |
| 删除的会话立即从侧栏消失；投影缓存记录随日志一起清理 | 会话删除后自动 |
| 可恢复的回收站：恢复与显式彻底删除 | 设置 → 存储清理 → **回收站** |
| Host 内已打开会话的延迟队列，下次启动执行 | 复核弹窗 → **安排删除（本次启动结束后自动执行）**；在设置里管理 |
| 清理策略：回收站位置/保留期/容量、审计日志、扫描预算、永久删除开关、Git 安全检查 | 设置 → 存储清理 → **清理设置** |
| 删除/跳过/恢复/清空的审计与上次启动结果 | 设置 → 存储清理 → 清理设置 → **最近删除** |
| 按规则挑会话（天龄、归档、大小、工作区、来源），预览后复核 | 设置 → 存储清理 → 会话 → **按规则选择** |
| 让 agent 只读检查可清理对象 | 工具 `cleanup_inventory` |

**删除是用户动作。** 面向 agent 的唯一入口是只读清单工具：模型可以报告有哪些对象、占多少空间、为什么被阻塞，但没有任何删除入口。

### 复核弹窗与逐行勾选

复核弹窗按*被复核目标*分组：一个会话或工作区一行，行下折叠它带出的子代理日志或目录内会话。每一行始终有复选框（单目标也一样），可以逐行勾选，也可以用「全选」/「反选」；只有勾选的目标进入计划，取消勾选会立即按剩余目标重新规划，空选择会保留所有行、提示「请至少选择一个目标」并禁用删除按钮。重新规划在途时，已勾选但尚未进入新计划的行显示「重新规划中…」，合计位置显示「正在重新计算复核结果…」，不会把上一版计划当作当前结果。永久删除一次只允许一个工作区目录：若勾选变化让计划跨过这个上限，界面会自动回落回收站并说明原因，而不是发出会被 Host 拒绝的永久计划。若重新规划后计划里仍出现已取消勾选的目标（例如工作区目录清扫把它带了回来），客户端会直接失败（`UNCHECKED_TARGET_LEAK`）且**不发出删除请求**。

### 会话家族树（0.6.0）

复核弹窗里的子代理日志不再是平铺列表，而是一棵按 `parentSessionId` 链深度优先排序、每层缩进一级的**树**：每个节点显示标题、大小与 `子代理`/`派生` 徽标，并带自己的复选框。父行复选框仍然只代表「根目标本身」；「同时删除子代理会话」开关与树是同一集合的两种视图——开关打开表示整族（`includeDescendants: true`），取消勾选任意节点会把开关关掉，并改为提交**显式目标集合**（已勾选的行 + 已勾选的节点，`includeDescendants: false`），Host 只会计划点名的日志。勾选一个节点会连带选中它的子树，取消则连带取消；子树只选中一部分时父节点渲染 `aria-checked="mixed"`，组头显示 `已选 n/m 条日志`，「全选」/「反选」对行与节点同时生效。

工作区「清空会话」批次里同样有这棵树，取消勾选的节点会记入该批次的排除集合，后续补页不会把它带回来。**删除工作区目录**不显示树：目录内会话由「路径在目录内」谓词扫入、不由 id 指定，控制项仍是「同时删除该目录内的会话记录」开关加行复选框。只要计划里出现既不是已勾选行、也不是已勾选节点的条目，复核就会以客户端码 `UNCHECKED_TARGET_LEAK` 失败关闭，不发送删除请求。

### 用量洞察（0.6.0）

「设置 → 存储清理 → 会话」有一个可选的**用量**开关（插件自有的 `localStorage` 键，默认关闭）。打开后，在 Host 支持的前提下每行多出「令牌」与「缓存命中」两列（悬停显示缓存命中率），多出「按用量排序」，有子代理的父行还会显示「本会话」与「含子代理合计」两个数：前者只统计该会话自己发出的请求，后者再把它名下的子代理会话加进来。单行用量尚未取到（或读不出）时显示 `—`，而不是 0。

用量通过 Host 的查询接口（`sessionQuery.readSession(id)`）从每个会话**自己的**日志折叠，不直接打开日志文件（日志可能压缩，只有 Host 的持久化栈能解码）。折叠规则：

- 只统计模型回复事件（`assistant/message` 且带 `data.usage`），其他事件不计。
- **fork 不重复计入祖先**：日志开头 `inheritedEventCount` 个事件是继承来的祖先前缀，从它之后才开始折叠；如果继承计数覆盖整个日志，该会话自己的用量为 0。
- 同一请求只计一次：按模型消息 id 去重，重复消息 id 计入 `duplicateRequests`；没有可用 id 的请求仍然计数，但结果标记 `complete: false` 并给出原因。
- 四个桶：缓存读（`cacheReadTokens`）、未命中输入（`inputTokens + cacheWriteTokens`）、缓存写（`cacheWriteTokens`）、输出（`outputTokens`）；总 token = 未命中 + 缓存读 + 输出。缓存写入同时保留在未命中桶与缓存写桶里，保证三段占比不重复、可加到 100%。
- 缓存命中率 = 缓存读 ÷（缓存读 + 未命中）。
- Host 侧按 `(eventCount, sizeBytes)` 缓存最多 200 个会话的折叠结果，日志变化才重算；缓存不落盘。
- 折叠只读：不打开写句柄、不会让会话变 live；某条日志读失败只影响该 id（出现在 `failed` 里），不会拖垮整个请求。

Host 没有查询接口时（`inventory.capabilities.usage` 为 `false`），用量列隐藏并说明原因，列表本身照常可用。

### 打开文件夹与缓存目录（0.6.0）

Host 平台有目录打开器时（macOS、Windows、Linux；`inventory.capabilities.openPath`），这些位置会出现**打开文件夹**入口：工作区行、会话行、回收站条目、复核弹窗摘要，以及回收站页签头部的**打开缓存目录**。

调用只传 `kind` 与 `id`——`workspace` / `session` / `trash` / `cache`——**从不传路径**：Host 用 `id` 自己解析目录（工作区目录、会话目录、回收站条目目录，或 `<DSH_HOME>/storages/session_projcache`），再交给平台打开器。因此界面无法要求打开任意路径，Host 也不会相信调用方给出的路径。失败按普通错误文案呈现：平台没有打开器（`OPEN_UNAVAILABLE`）、打开器无法启动（`OPEN_FAILED`）、目标已不存在或读不出（`IO_ERROR`）、回收站条目未知（`TRASH_ENTRY_UNKNOWN`）、工作区或会话已不存在（`UNKNOWN_WORKSPACE` / `UNKNOWN_SESSION`）。调用是 fire-and-forget：Host 在**启动器进程被创建后**就返回，不等它退出，所以常驻的启动器不会把请求挂住；文件管理器最终是否聚焦不算失败。复核弹窗摘要上的入口只在**单目标**复核里出现（多目标摘要无法唯一指名一个目录），其无障碍名使用目标标题而不是原始路径。macOS 上以 `.app` / `.bundle` / `.workflow` / `.pkg` 结尾的目录是应用包，朴素 `open` 会**执行**它，因此 Host 改用 `open -R` 在 Finder 中显示。

### 家族树的目标上限

一次复核的计划最多携带 64 个目标（Host 的安全预算）。当勾选的行 + 逐节点选择的日志超过预算时，弹窗会**在发出请求之前**以客户端错误 `TOO_MANY_TARGETS` 失败，并提示缩小选择或分批清理；「清空工作区」批次不会失败，而是自动缩小本批（行 + 节点 ≤ 64），把剩余行放回队列交给后续批次。单个家族本身就超过预算时同样给出该提示。

### 删除之后（0.6.0）

- **投影缓存不残留。** 会话的日志目录删除后，若 Host 暴露存储域服务（`inventory.capabilities.projectionCache`），插件会一并删除该会话在 `session_projcache` 中的记录，删除结果里该条带 `cacheDropped: true`。服务缺失、域已关闭或删除抛错时静默跳过（`cacheDropped: false`），删除本身照常成功——那只是一份可随时重建的折叠缓存，不是用户数据，所以不会产生计划警告，也不会让删除失败。
- **侧栏即时更新。** 每个成功（`trashed` 或 `deleted`）的会话项都会让 Host 发出 DSH 自带的 `api-session/removed` 事件，所有已连接的浏览器像会话被释放一样立刻移除侧栏行，不需要刷新页面。发事件是尽力而为：最小 Host 或测试上下文没有 `emit` 时直接忽略，不会改变删除结果。

### 清空工作区会话

「清空工作区会话…」只删除一个工作区名下的会话日志，工作区目录与注册信息原样保留。流程是预检 → 复核第一批（最多 64 条）→ 确认后自动分批执行其余部分：预检把本次启动中打开/运行的日志列为跳过并说明数量（同一会话不会因分页重复计数），每批执行后按实际已删除的 id 更新剩余队列；某个目标若已被其他进程删掉，插件会重读工作区、重建待删队列继续，而不是整轮失败。结果页只在完全没有残留（无失败、无跳过、无排除、未提前停止）时自动关闭，否则保留到你点「完成」。当所有日志都要等重启后才能删除、当前没有可执行批次时，复核弹窗会提供「安排删除」，并在排队结果里说明还有多少条未包含。

## 安全模型

从一次点击到一个字节被删除，中间有四道闸。

### 1. 先计划，后执行

删除请求先向 Host 要一份*计划*：具体目标、包含的文件与目录、总字节数、警告（例如 Git 未提交改动）、阻塞项（例如 live 会话），以及永久删除工作区目录时的「输入目录名」要求。计划一次性、5 分钟内有效。执行前会重新校验世界：目标被移动、身份变化或出现新的阻塞，Host 就以 `STATE_CHANGED` 拒绝，一个字节都不动。

### 2. 默认进回收站

删除会把目标移动到 `<DSH_HOME>/trash/dsh-cleanup/` 下的回收站，而不是直接抹掉，所以常见的误操作可以恢复。永久删除是显式的第二种模式；复核弹窗在选中永久模式时会明确说明**它不可撤销**，而默认的回收站会把日志留在磁盘上，直到你彻底删除。永久删除工作区目录还要**手动输入目录名**，且一份永久计划最多包含一个已存在的工作区目录——一个输入的名称绝不能授权删除另一个目录。批量永久删除会被拒绝；多个目录请逐个删除，或改用回收站模式。

跨磁盘卷时 `rename` 会失败。插件拒绝这种情况，让你明确选择永久删除，而不是偷偷把几个 G 的数据复制到回收站所在磁盘。

### 3. 只删已注册、路径未漂移的目标

工作区目录只能通过 DSH 注册表里的工作区 id 删除。执行前会重新 `lstat` + `realpath`，路径必须仍等于注册表保存的规范路径；符号链接或被替换的目录一律拒绝。静态路径策略还会拒绝文件系统根目录、家目录、`~/.dsh`、Host 进程工作目录**及其祖先目录**、回收站自身、包含 `~/.dsh` 的路径，以及层级过浅、不可能是项目的路径。

因此「能删的东西」的集合 = 「DSH 认识它」∩「文件系统此刻仍然同意」，并在执行时重新检查。

### 4. 绝不碰正在使用的会话

DSH 会让 Agent 及其会话写句柄存活到进程结束，并且没有公开释放 API。写句柄仍存在时删除会话日志会损坏日志。插件在即时删除与延迟删除时都会探测会话持久化的写句柄，包括**另一个 Host 进程**持有的会话：运行中回 `SESSION_RUNNING`，已打开但空闲回 `SESSION_LIVE`。只要有 live 会话的工作目录在某个工作区目录内，删除该工作区目录同样被阻塞。

对于当前 Host 内已打开的会话，复核弹窗提供**安排删除（本次启动结束后自动执行）**：复核过的目标与选项写入 `<DSH_HOME>/cleanup/deferred.json`，在下次 Host 启动时尽早执行（尽力而为：在浏览器恢复任何会话之前），走完整的计划 → 准入 → 执行管线执行。被阻塞的条目会记录原因而不是整轮失败，队列可在设置里查看和取消。运行中的插件热重载刻意不消费该队列。

### 记账护栏

- **回收站归属校验。** 回收站条目带归属标记；`trashRoot` 只能指向本插件专用的目录，外来目录既不会被列出，也不会被删除，因此把回收站指到无关目录不会毁掉那里的内容。
- **自有状态。** 延迟队列、设置覆盖文件与审计日志位于 `<DSH_HOME>/cleanup/`，仅所有者可读写，并采用原子写。它们属于用户可写状态，不是安全边界。

## 安装

```sh
# 从 npm 安装（包发布之后）
dsh plugin --profile web add dsh-cleanup@0.6.2

# 从 GitHub 安装（v0.6.2 是 tag，指向固定提交；需要严格 pin 时用 `git rev-parse v0.6.2` 换成完整 sha）
dsh plugin --profile web add github:xiaoyangren6514/dsh-cleanup#v0.6.2

# 从本地 checkout 安装
git clone https://github.com/xiaoyangren6514/dsh-cleanup.git
dsh plugin --profile web add ./dsh-cleanup
```

安装后**刷新一次浏览器页面**：Host 半部会热更新，但浏览器半部是新的客户端模块，页面需要重新加载。卸载用 `dsh plugin --profile web remove dsh-cleanup`；回收站与 `<DSH_HOME>/cleanup/` 状态会保留。

从本地 checkout 链接安装的目录在使用期间必须留在原地，否则 profile 可能无法启动。

## 环境与兼容性

- **DSH 0.2.2-rc.1 与 0.2.2-rc.2** 已验证；`engines.dsh: >=0.2.2-alpha.3 <0.3.0` 会在安装/启用前检查，不兼容的运行时被拒绝，而不是半支持运行。rc.2 新增的精确版本插件兼容检查只影响把 `@deepseek-ai/*` 依赖写死到精确版本的插件，本插件声明的是版本区间，不受影响。
- Host 半部需要 **Node.js ≥ 20**。
- **Web 界面**——浏览器半部通过 DSH 客户端模块加载器与 `shell.overlay`、`settings.section`、`contextMenu.*` 扩展点注册。
- **macOS（`darwin`）、Linux 与 Windows（`win32`）**——`dsh.bundle.platforms: ["darwin", "linux", "win32"]`。Windows 上使用盘符根与反斜杠路径：盘符根（`C:\`）、系统目录（`C:\Windows`、`Program Files`、`ProgramData`）与家目录的上级都受保护，路径比较按不区分大小写处理，目录层级按「相对盘符根的段数」计算，因此 `C:\proj` 与 `/proj` 一样被视为顶层目录而拒绝。映射为符号链接的 junction 与符号链接同等拒绝。POSIX 专属的权限用例在 Windows 上跳过。这些 Windows 语义已实现并有单元测试覆盖，但本版本只在 macOS 上做过完整验证（见[已知限制](#已知限制)）。
- **本地文件系统路径**——不感知远程或非本地文件系统提供者。回收站必须与目标在同一卷，否则一律拒绝并提示改用永久删除。

## 语言

插件界面文案（设置页、复核弹窗、菜单、通知）只提供**简体中文与英文**。DSH 0.2.2 另内置日语、西班牙语、法语、德语、俄语、巴西葡萄牙语；在这些界面语言下，本插件回落为英文，不会展示未翻译或机翻内容。插件管理器显示元数据（`locale/*.json`）保留**八种语言**。

长文详情以**中文为默认文档**（即本文），英文版见 [DETAIL.en.md](https://github.com/xiaoyangren6514/dsh-cleanup/blob/main/docs/DETAIL.en.md)：中文界面读本文，英文界面读英文版，未单独翻译的语言读中文默认文档。

## 隐私

插件完全在本地工作：

- 不发起对外网络请求，无遥测、无分析、无远程同步；浏览器半部只调用同源的本地 Host API。
- 只读取 Host 已经在管理的路径（工作区目录、会话日志、自己的回收站与状态文件），只写入 `<DSH_HOME>/trash/dsh-cleanup/` 与 `<DSH_HOME>/cleanup/`。用量洞察从 Host 的查询接口读取日志并在内存里折叠，不落盘、不发送。
- 不读写 DSH 自身配置、不修改 profile 的 `cordis.patch.yml`、不把会话内容发送到任何地方。
- Git 安全检查只读执行本地 `git` 并仅报告计数；可在清理设置里关闭；Git 不存在、目录不是仓库或探测超时时静默跳过。

## 已知限制

下面这些是 DSH 或本版本插件的性质，不是待修的 bug：

- **活会话不能立即删除。** DSH 会把打开过的会话 Agent 及其日志写句柄保留到 Host 进程结束，而且没有释放接口；此时删日志会损坏它。复核弹窗提供**安排删除**，队列在下次 DSH 启动、任何会话恢复之前执行；共享同一个 `$DSH_HOME` 的另一个 Host 进程打开的会话同样会被拒绝。
- **用量需要 Host 的查询接口。** 只有 Host 暴露 `sessionQuery.readSession(id)` 时才会出现「用量」视图；没有该接口时相关列隐藏（`inventory.capabilities.usage` 为 `false`）。用量按可回放校验的日志折叠，所以 fork 继承来的历史不计入 fork 自己的用量，重复的请求只计一次。
- **投影缓存清理需要 Host 的存储域服务。** 只有 Host 暴露该服务时，删除会话才会连同其 `session_projcache` 记录一起删除；否则静默跳过（`inventory.capabilities.projectionCache` 为 `false`，删除结果里 `cacheDropped: false`）。该记录只是可随时重建的折叠缓存，不是用户数据。
- **回收站永不自动清理。** 保留天数与容量上限只产生警告，由用户主动清理；回收站里的内容在被彻底删除前一直占用磁盘——这正是「恢复」能够成立的前提。
- **永久删除不可撤销。** 默认的回收站模式会把日志留在磁盘上，直到你彻底删除；永久模式会立即抹掉。永久删除工作区目录还要求输入目录名。
- **附件不会被清理，搜索索引由 Host 负责。** 删除范围是会话的存储日志（以及它的子代理日志）；会话产生的附件文件不在其中，DSH 的搜索索引由 Host 自行协调。
- **插件状态不是安全边界。** 队列、设置覆盖、审计日志与回收站元数据都是 `<DSH_HOME>/cleanup/`（以及 `<DSH_HOME>/trash/dsh-cleanup/`）下用户可写的文件；同权限进程可以修改它们，也可以直接删文件。「删除是用户动作」是本插件自身界面的约束，不是沙箱。
- **打开文件夹是尽力而为。** 只有 Host 平台有打开器（macOS、Windows、Linux）时才显示入口；目录由 Host 自己解析并要求系统打开，文件管理器最终是否聚焦不会被报告为失败。
- **Windows 语义已实现，但没有在 Windows 机器上验证过。** 盘符/UNC 根、大小写不敏感比较、层级计算与 junction 拒绝都有单元测试覆盖，但本版本只在 macOS 上做过完整验证。
- **测试是单元级的。** Host 与浏览器逻辑由 `node --test` 加假服务与真实临时目录覆盖；没有在真实 DSH GUI 中运行的自动化端到端测试，浏览器接线与 Host 版本兼容性靠手工验证。
