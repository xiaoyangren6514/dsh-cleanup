# 常见问题（FAQ）

> 适用版本：dsh-cleanup 0.6.0 · DSH 0.2.2-rc.1。
> 文中 `~/.dsh` 指当前 profile 的 DSH home；插件状态文件位于 `~/.dsh/cleanup/`，回收站位于 `~/.dsh/trash/dsh-cleanup/`（除非在清理设置里配置了专用的 `trashRoot`）。

## 安装、升级与卸载

### 怎么安装？
装进一个 DSH profile，然后刷新一次浏览器页面（Host 半部热更新，浏览器半部是新客户端模块，必须重新加载页面）：

```sh
# npm（包发布之后）
dsh plugin --profile web add dsh-cleanup@0.6.0

# GitHub，固定到 v0.6.0 tag（指向固定提交；需要严格 pin 时用 `git rev-parse v0.6.0` 换成完整 sha）
dsh plugin --profile web add github:xiaoyangren6514/dsh-cleanup#v0.6.0

# 本地 checkout
git clone https://github.com/xiaoyangren6514/dsh-cleanup.git
dsh plugin --profile web add ./dsh-cleanup
```

`web` 是示例 profile 名，替换成你实际使用的 profile。

### 怎么升级？
用新版本执行一次 `dsh plugin --profile web add dsh-cleanup@<新版本>`（或重新添加 GitHub 提交），然后刷新页面。升级不会动回收站和 `~/.dsh/cleanup/` 里的状态；旧版本留下的队列/设置会被新版本继续读取。

### 怎么卸载？
`dsh plugin --profile web remove dsh-cleanup`，或在设置 → 插件里禁用/移除该 bundle。卸载**不会**删除回收站里的文件和 `~/.dsh/cleanup/` 下的状态文件，需要时手动处理。

### 为什么装完看不到菜单/设置页？
Host 半部通常已经通过 HMR 生效（只读工具 `cleanup_inventory` 可以直接调用），但浏览器半部是新的客户端模块，**必须刷新页面**。刷新后仍然没有：确认 bundle 已在设置 → 插件里启用，且 Host 平台受支持（见下）。

### 支持哪些平台？
macOS（`darwin`）、Linux 与 Windows（`win32`），三者都写在 `dsh.bundle.platforms` 里。Host 侧需要 Node.js ≥ 20。

Windows 上的行为：

- 路径按 Windows 语义处理：盘符根（`C:\`）、系统目录（`C:\Windows`、`Program Files`、`ProgramData`）与家目录的上级都受保护；`C:\proj` 与 `/proj` 一样被当作顶层目录拒绝。
- 路径比较不区分大小写；junction 与符号链接同等拒绝，不会顺着链接删到链接之外的内容。
- 回收站必须与目标在同一卷：`C:` 上的目录不能移入 `D:` 上的回收站，插件会拒绝并提示改用永久删除。
- 被其他进程占用或被设为只读的文件/目录会让移动或删除失败（Windows 的 `EPERM`/`EBUSY`），解除占用后重试即可。

注意：这些 Windows 语义已实现并有单元测试覆盖，但本版本只在 macOS 上做过完整验证，没有在 Windows 机器上跑过破坏性路径。

### 插件会联网吗？
不会。没有对外网络请求、遥测或远程同步；浏览器半部只调用同源的本地 Host API。插件只读写本机 Host 已管理的路径（工作区目录、会话日志、自己的回收站与状态文件）。详见 [DETAIL.md](DETAIL.md) 的「隐私」一节。

### 它和「插件市场」是什么关系？
DSH 0.2.2-rc.1 没有官方插件市场或官方索引。Discover 页签由可选的实验性 plugin-market bundle 提供，默认不配置任何索引；社区索引（例如 awesome-dsh-plugin.com、dshopen.org）需要用户自己添加索引 URL。安装本身始终是上面那条 `dsh plugin ... add` 命令。

## 删除与恢复

### 删除后还能恢复吗？
默认**移入回收站**，在「设置 → 存储清理 → 回收站」里可以「恢复」或「彻底删除」。默认的回收站会一直把日志留在磁盘上，直到你主动彻底删除——这也正是「恢复」能够成立的原因。**永久删除不可撤销**：复核弹窗在选中永久模式时会明确说明这一点；永久删除工作区目录还要求输入目录名。

### 为什么「彻底删除」还要再点一次？
所有不可恢复的操作都是两步确认（第一次点击进入预备状态，400 ms 内第二次点击才执行），也可以点击别处、按 Esc 或让窗口失焦来解除预备状态。「清空回收站」这类批量操作同样如此。

### 回收站目录能随便指吗？
不能。配置的 `trashRoot` 只能指向本插件专用的目录：回收站条目带归属标记，外来目录既不会被列出，也不会被删除。因此把回收站指到一个无关目录不会破坏那里的内容（但恢复/清理只对本插件的条目生效）。

### 工作区目录删掉后，里面的会话去哪了？
默认「清理工作区」会连同其内会话一起处理（复核弹窗里有条目计数）。只想删目录、保留会话时取消勾选对应选项；反之只想删一个工作区的会话、保留目录与注册，可用「清空工作区会话…」，其他范围可用「会话」页签或「按规则选择」向导。

### 「清空工作区会话」和「删除工作区目录」有什么区别？
「删除工作区目录」删掉真实目录（默认连带目录内会话），工作区随后从列表里消失；「清空工作区会话」**只删除该工作区的会话日志**，目录与注册信息保留，适合「工作区还要用、历史会话不要了」。清空会先预检、复核第一批（最多 64 条），确认后自动分批执行其余部分；本次启动中打开/运行、暂时不能删的会话会被跳过并计数（重启后可再清一次），结果页只有在完全没有残留时才自动关闭，否则保留到你点「完成」。

## 用量与家族树

### 为什么没有「用量」列／用量为什么显示「—」？
「用量」是 0.6.0 起新增的可选视图，**默认关闭**：在「设置 → 存储清理 → 会话」把「用量」开关打开后，才会出现「令牌」与「缓存命中」两列（悬停显示缓存命中率），以及「按用量排序」。用量由 Host 的查询接口从每个会话**自己的**日志折叠而来：fork 继承来的祖先事件不计入，同一请求按消息 id 去重，只统计模型回复（`assistant/message`）里的 usage；缓存命中率 = 缓存读 ÷（缓存读 + 未命中）。有子代理的父行还会显示「本会话」与「含子代理合计」两个数：前者只算该会话自己发出的请求，后者再加上它名下的子代理会话。

显示「—」表示该会话的用量还没取到（或 Host 读不出这条日志），**不是 0**。如果整列都看不到：当前 Host 没有提供查询接口（`inventory.capabilities.usage === false`），这是 Host 能力问题而不是插件故障；列表本身不受影响。

### 家族树里勾选一个父节点会怎样？
复核弹窗里的子代理日志以树呈现，每个节点有自己的复选框：勾选一个节点会连带选中它的子树，取消则连带取消；子树只选中一部分时父节点显示三态（`aria-checked="mixed"`），组头显示已选数量。父行复选框仍只代表「根目标本身」。「同时删除子代理会话」开关打开表示删除整族（`includeDescendants: true`）；取消勾选任意节点会把开关关掉，改为提交**显式目标集合**（已勾选的行 + 已勾选的节点，`includeDescendants: false`），Host 只计划点名的日志，所以可以只保留某条失控的子代理日志。「全选」/「反选」对行与节点同时生效。

注意：**删除工作区目录**没有家族树——目录内会话是按「路径在目录内」扫进来的、不由 id 指定，控制项仍是「同时删除该目录内的会话记录」开关加行复选框。

## 会话正在使用中

### 为什么活会话只能安排删除？
DSH 会让打开过的会话 Agent 及其日志写句柄存活到 Host 进程结束，而且不提供释放接口；在写句柄仍存在时删日志会损坏它。所以即时删除一定被阻塞（运行中 `SESSION_RUNNING`、已打开 `SESSION_LIVE`），复核弹窗给出唯一安全的替代路径「安排删除（本次启动结束后自动执行）」：把这次复核排队到下次启动、在任何会话恢复之前执行，仍然走完整的计划 → 准入 → 执行管线。共享同一个 `~/.dsh` 的另一个 Host 进程打开的会话同样如此。

### 提示「该会话正在使用中，删除会损坏日志」怎么办？
DSH 不会释放已被 Agent 打开的会话写句柄，进程内强删会损坏或重建日志，所以这是**安全拦截**，不是故障。插件对即时删除与延迟删除都会探测会话持久化的写句柄，**包括另一个 Host 进程持有的会话**——另一个 DSH 进程正在用的会话同样会被拒绝。

在复核弹窗里选择「安排删除（本次启动结束后自动执行）」：插件把这次删除排队到**下次启动 DSH 时**尽早执行（尽力而为：在浏览器恢复任何会话之前），仍然走完整的计划/准入/执行管线。也可以在「设置 → 存储清理」的待删除横幅里查看/取消。

### 下次启动时如果会话又被打开了？
启动执行前会重新校验：会话仍然存活（本进程或另一个 Host 进程持有写句柄）→ 跳过并在「上次未完成」里记录原因（`SESSION_LIVE`），**不会**动它的日志。可稍后重新安排或忽略。

### 「上次未完成」是什么？
最近 20 条被跳过/失败的排队删除，带错误码和原因。可以「重新安排」（重新入队）或「忽略」（从列表移除）。它们不会自动重试，避免无人值守时反复尝试。

## 队列与延迟删除

### 延迟队列存在哪？安全吗？
`~/.dsh/cleanup/deferred.json`，仅所有者可读写；跨进程用锁文件串行化（冲突时返回 `DEFERRED_BUSY`）。队列是**用户状态**：同权限进程本就能直接删文件，插件不把它当安全边界；它的价值是「不会因为进程重启丢失安排、不会误删复核范围外的对象」。

### 排队的删除会不会在执行时误删别的东西？
不会。每条记录冻结了**复核时的条目集合**与（永久删除时的）**已确认目录身份**（路径 + 设备 + inode）：复核后新建的会话/子目录不会被执行，目录被替换/移动会以 `PATH_CHANGED` 跳过；已消失的复核项允许继续。启动执行仍会重新做存活、路径与准入检查。

## 保护规则

### 哪些路径永远不能删？
文件系统根目录、家目录、`~/.dsh`、**Host 进程工作目录及其祖先目录**、回收站自身、包含 `~/.dsh` 的路径、层级过浅的路径、符号链接，以及任何不是通过 DSH 注册表登记的路径。工作区目录在删除前还会重新解析规范路径，任何漂移都会拒绝。

### 计划会过期吗？
会。计划一次性、5 分钟内有效；执行前会重新校验世界，任何变化（目标移动、出现阻塞、计划被用过）都会拒绝并要求重新生成计划。过期的计划返回 `PLAN_EXPIRED`。

### 为什么删大工作区时提示「超过一份计划的会话上限」？
一份计划最多删除 1000 条会话日志（含子代理会话），用来限制单次复核操作的影响面。会话很多时先在「会话」页签分批删除，再回到工作区页签、取消勾选「同时删除该目录内的会话记录」后删除目录。

### 从 0.3.0 升级后，旧回收站条目还能用吗？
能。0.4.0 起回收站条目带 `.dsh-cleanup-entry` 归属标记；0.3.0 写入的旧条目没有标记，但 `meta.json` 形状严格匹配时仍会被列出、恢复和清理。把 `trashRoot` 指向一个已有数据的无关目录时，那些目录不会被当成回收站条目处理。

例外：0.3.0 在「回收站元数据写入失败且回滚也失败」的极端情况下，可能留下一个没有 `meta.json` 的 `payload/` 目录。这类残留 0.4.0 不再自动列出（没有归属依据），数据仍在原 `trashRoot` 下，请手动处理；如需插件后续支持一次性迁移，可在仓库提 issue。

## 回收站生命周期

### 回收站会自己清理吗？
**不会**。只会在「回收站」页签给出警告：超过保留天数或容量上限时，建议「清理最旧条目」，由用户点击并二次确认后才删除。保留期/容量在「清理设置」里配置（0 = 关闭警告）。

## 缓存与打开文件夹

### 删了会话为什么缓存目录还有东西？
两种情况：

1. **默认是回收站模式。** 日志被移动而不是抹掉，会一直留在 `~/.dsh/trash/dsh-cleanup/<条目>/payload/` 里占用磁盘——这正是「恢复」的基础，只有你「彻底删除」后才真正释放。
2. **投影缓存可能被跳过。** 删除会话时，插件会尽量把该会话的 `session_projcache` 记录一起删掉，但这要求 Host 提供存储域服务。Host 没有该服务时这一步会**静默跳过**（`inventory.capabilities.projectionCache === false`，删除结果里该条 `cacheDropped: false`）。留下的记录只是可随时重建的折叠缓存，**不是用户数据**，不影响删除成功，也不代表还有日志没删。可以在回收站页签用「打开缓存目录」去看（见下一条）。

### 打开文件夹失败怎么办？
「打开文件夹」入口只出现在 Host 平台有目录打开器时（macOS、Windows、Linux；`inventory.capabilities.openPath`）。界面只提交一个 `kind`（`workspace` / `session` / `trash` / `cache`）与一个 `id`，目录由 Host 自己解析，所以不会、也不能让插件打开任意路径。失败时按错误码判断：

- `OPEN_UNAVAILABLE`：当前平台没有打开器（例如平台不在 `darwin`/`win32`/`linux` 之内）。
- `OPEN_FAILED`：打开器无法启动（系统环境问题）。
- `IO_ERROR`：目标目录已不存在或读不出——会话/工作区/回收站条目可能刚被删除，刷新页面后重试；「打开缓存目录」在 Host 还没有生成该目录时也会这样。
- `TRASH_ENTRY_UNKNOWN`：回收站条目已不存在（可能已被清空或恢复）。
- `UNKNOWN_SESSION` / `UNKNOWN_WORKSPACE`：会话或工作区已不存在，刷新后重试。

调用是 fire-and-forget：Host 解析出目录就会返回成功，文件管理器最终是否聚焦不算失败，所以偶尔「没有反应」时先检查系统默认文件管理器。

## 设置与审计

### 设置存在哪里？为什么不在「插件配置」里改？
设置页保存到插件自有文件 `~/.dsh/cleanup/settings.json`，优先级：该文件 > profile 行配置 > 默认值；修改**立即生效**，不需要重启。这样做是为了不写用户的 `cordis.patch.yml`、不触发插件重启。

### 审计日志记录什么？能防篡改吗？
`~/.dsh/cleanup/audit.jsonl`：每次删除/跳过/恢复/清空/入队/取消/重新安排各一条，另有每次启动的汇总；超过上限时轮转为 `audit.jsonl.1`（只保留一代）。它是**诊断用途、不防篡改**：同权限进程可以改它。它的价值是事后追溯「谁在什么时候删了什么」和「上次启动为什么跳过」。

### 为什么设置页显示「仅本次运行生效」？
设置的持久化文件不可写（权限/磁盘问题），本次运行仍按新值生效，但重启后会回到旧值；按提示修复目录权限后重新保存即可。

## Git 安全检查

### 删除工作区前会检查 Git 吗？
会，但**只读且只警告**：计划阶段读取 `git status` 与未推送提交数，在复核弹窗列出「N 个未提交/未跟踪改动」「N 个未推送提交」。没有 `git`、目录不是仓库、或探测超时（3 秒/条）时静默跳过，**从不阻塞**删除。可在「清理设置 → 高级」里关闭。

## Agent 与工具边界

### Agent 能自己删除文件吗？
**不能。** 插件对 Agent 只暴露一个只读的 `cleanup_inventory` 扫描工具；删除只能由用户在界面上确认发起。这与 DSH 自身文件权限无关——它约束的是本插件的工具面。

### Agent 能「提议」清理并让我一键确认吗？
Action Card 形式的提议需要 DSH 的可选 `action-cards` bundle（出厂默认未启用），且该机制要求插件提供 Zod schema 与配套 skill；本插件不依赖这些包，暂未内置。当前流程是：Agent 用只读工具给出建议，用户在设置页复核操作。

## 界面与语言

### 界面语言如何切换？
跟随 DSH 的界面语言。本插件的 UI 字典只有**简体中文与英文**：DSH 内置的另外六种界面语言（日语、西班牙语、法语、德语、俄语、巴西葡萄牙语）在本插件页面上**回落为英文**，不会出现机翻内容。插件管理器中显示的标题/描述另有八种语言元数据，长文详情提供英文与中文两版。

### 为什么 DSH 切到日语后插件页还是英文？
同上：插件只为 zh/en 提供 UI 字典；DSH 内置的日语没有对应翻译，语言链最终落到英文。这是当前有意的取舍（不做无审校的机翻），后续可以按语言逐个补齐。

## 性能与排障

### 删除大目录很慢/界面卡住吗？
删除是同步执行的，界面会显示「已用时 N 秒」与正在处理的数量；目录大小预览有 30 秒缓存（按目录设备/inode 判定，替换目录不会命中旧缓存），但**删除路径永远使用实时数据**，不会因为缓存而少删/多删。

### 会话很多时设置页会卡吗？
清单一次读取（有上限并显示截断提示，默认上限 2000 条会话），清理向导只对这份快照做筛选，不会逐会话扫盘；大目录的尺寸预览按需计算并短时缓存（默认预算 20 万条目 / 每目录 4 秒，超出显示下界）。用量视图只在打开后按需分批读取（每批最多 200 个会话），并且会复用 Host 侧的折叠缓存，不会每次刷新都重读全部日志。

### 插件页一直显示「加载失败」？
先点「重试」；仍失败时检查 Host 日志与 profile 的 bundle 状态（`dsh plugin --profile <name> list` 或设置 → 插件）。常见原因是 bundle 未启用、Host 平台不受支持，或 DSH 版本超出 `engines.dsh` 声明的兼容范围。
